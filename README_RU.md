# DARKLS VPN Panel 1.1.2

Панель для уже настроенного ASUS TUF-BE6500 arm64, LAN 192.168.50.0/24, Xray/XHTTP/Reality, dnsmasq 10535 и USB-автозапуска. Накопительное обновление поверх 1.0.1–1.1.0. Серверные параметры VPN и пароль сохраняются. Эта версия проверена на тестовой Linux-системе; на реальном роутере требуется проверка после установки.


## Исправления 1.1.2

- CPU на первом открытии вычисляется по двум чтениям `/proc/stat` с интервалом 200 мс; больше не требуется ждать следующего 30-секундного обновления. Если счётчики недоступны, показывается «CPU недоступен» вместо бесконечного «Первый замер».
- В группу Instagram добавлен `fbsbx.com`: на присланном скриншоте тайм-аут возникал во фрейме `www.fbsbx.com`, используемом страницей проверки. Суффикс включает поддомены. Исправление для существующей группы применяется один раз при установке, сохраняет имя и включённое/выключенное состояние. Facebook включать не требуется. DNS helper перечитывается без перезапуска Xray. Последующее осознанное удаление домена пользователем не отменяется каждым обновлением.
- После обновления закрой страницу проверки Instagram. На Windows выполни `ipconfig /flushdns`, полностью закрой браузер и заново открой Instagram. Это исключает старое DNS-состояние. Исправление маршрута к недостающему домену не гарантирует успешную проверку аккаунта: решение проверки остаётся на стороне сайта.
- Установщик сохраняет также доменные/DNS-файлы для согласованного отката после миграции.
- Ядро Xray 26.10.10 не меняется. Для установки загрузить `DARKLS-VPN-Panel-v1.1.2.zip` в Настройки → обновление и нажать Ctrl+F5 после завершения.

## Новое в 1.1.1

- Журналы Xray, helper DNS, панели и установщика проверяются раз в 15 секунд. При размере больше 2 МиБ оставляется хвост до 256 КиБ. Это периодическая граница, а не жёсткий лимит на каждую запись: между проверками журнал может вырасти. Последние строки сохраняются, более старые удаляются. Xray запускается с append-дескриптором, чтобы усечение не создавало sparse-файлы. При первом переходе установщик один раз перезапускает VPN, если он включён. DNS debug-запись в конфиге панели по-прежнему выключена.
- Диагностика маршрута пишет «По правилам должен идти через VPN»: это проверка конфигурации и IP-набора, не доказательство прохождения пакета браузера.
- В диагностике появилась отдельная HTTPS-проверка семи сервисов с роутера через локальный SOCKS Xray. Разделены DNS-ошибка, тайм-аут, ошибка соединения/TLS, HTTP-ошибка и Cloudflare challenge. Redirect 3xx показывается как полученный ответ; переходы не выполняются. Проверка не отправляет cookies и не проверяет авторизацию, ответы модели, приложения или QUIC. Только фиксированные сервисы; произвольные URL не запрашиваются. Такие ошибки не запускают восстановление VPN.
- Раз в минуту автоконтроль дополнительно проверяет ключевые правила внутри цепочек TCP/UDP/DNS/YouTube и живой DNS-ответ через 1053 и 10535. Случайные имена не позволяют старому положительному кэшу скрыть отказ upstream. NXDOMAIN считается корректным DNS-ответом. Две неудачные проверки и интервал 180 секунд защищают от лишних перезапусков; отсутствие процессов/подключений цепочек исправляется прежним быстрым способом.
- CLI `--check-router` проверяет содержимое правил и DNS; `--maintain-logs` выполняет обслуживание журналов.
- Отдельный пакет Xray 26.10.10 arm64: официальный бинарник, проверка фиксированного SHA-256, версии/ELF и текущего конфига до отключения VPN. Старая копия ядра сохраняется на USB WINDOWS_10 и повторно проверяется перед заменой. Свободное место проверяется. При ошибке запуска или общей HTTPS-проверки выполняется попытка отката. Журнал незавершённой операции сохраняется в JFFS и обрабатывается при следующем запуске панели/восстановлении монитора. Для отката нужна подключённая исправная флешка.

### Установка 1.1.1

В панели 1.1.0: Настройки → обновление → выбрать `DARKLS-VPN-Panel-v1.1.1.zip`, ввести текущий пароль и дождаться завершения. Пароль и списки сохраняются. Затем Ctrl+F5. Архив ядра не загружать в веб-обновление панели (у него другой формат).

### Обновление ядра после установки панели

На компьютере в PowerShell, скачав `DARKLS-Xray-v26.10.10-arm64.zip` в Downloads:

```powershell
Expand-Archive "$env:USERPROFILE\Downloads\DARKLS-Xray-v26.10.10-arm64.zip" "$env:USERPROFILE\Downloads\DARKLS-Xray-v26.10.10-arm64" -Force
cmd /c 'tar -C "%USERPROFILE%\Downloads\DARKLS-Xray-v26.10.10-arm64" -cf - darkls-xray-update | ssh DARKLS@192.168.50.1 "tar -xf - -C /tmp"'
```

На роутере в SSH:

```sh
sh /tmp/darkls-xray-update/install-xray.sh
/jffs/xray/xray version
/jffs/xray/panel/darkls-panel --check-vpn
/jffs/xray/panel/darkls-panel --check-router
```

Во время замены ядра выбранные VPN-соединения переподключатся. После успешной установки папка `/tmp/darkls-xray-update` удаляется. Предыдущее ядро остаётся в `/tmp/mnt/WINDOWS_10/darkls-vpn-backups/`; не удалять его, пока нужен откат. Новый бинарник находится в JFFS, не запускается с флешки. Конфиг сервера не меняется.

Ручной откат при необходимости (SSH роутера):

```sh
/jffs/xray/panel/darkls-panel --rollback-xray
```

После ручного отката проверить `xray version` и `--check-vpn`. Сохранённая копия ядра — публичный исполняемый файл, конфиг с VPN-учётными данными на FAT-флешку не копируется. При нехватке места/отсутствии флешки установщик отказывается от замены; старое ядро сохраняется. ZIP официальный SHA256 `58e339e67827220175b3a1c6f66f48ccd086b79209f30ba1c0bcb47885d4c22a`; извлечённый xray SHA256 `fadf8d792889536a9410686f3d5c4df76ec7865b7aa2297495365759ffeb424c`.

Проверено локально: Go tests с race detector, vet, браузерные сценарии (включая распознавание challenge), успешное обновление панели/откат при отказе запуска, HTTP-загрузка обновления через панель, восстановление предыдущего ядра из проверенной копии при незавершённой операции. Новое ARM64-ядро на настоящем ASUS здесь не запускалось; `run -test` и HTTPS выполняются самим установщиком на роутере.

## Возможности

- Группы по назначению: видео, ИИ, соцсети, мессенджеры, музыка, чтение и авторы, новости и СМИ, сервисы и инструменты, 18+, свои группы. Назначение меняется в редакторе группы. Фильтр, поиск и прежние выключенные группы сохранены.
- Светлая/тёмная/системная темы с сохранением в браузере.
- Реальный статус HTTPS через VPN: время последнего успеха и ошибки, длительность проверки, последовательные неудачи, число автоматических восстановлений и последняя причина. Файл статистики в RAM, сбрасывается при перезагрузке. Зелёный статус требует свежую успешную проверку и работающие процессы/правила; одних процессов недостаточно.
- «Проверить сейчас» выполняет HTTPS через SOCKS Xray. «Проверить сайт» использует DNS роутера, показывает совпавшие группы, IPv4 и наличие адреса в VPN-наборах, учитывая режим устройства, NAT-hook, служебные исключения и общий выключатель. Результат относится к устройству, открывшему панель. Это диагностика DNS/отбора IP, не скачивание содержимого сайта и не трассировка всех возможных вручную добавленных правил.
- Устройства: вся сеть / только выбранные / все, кроме выбранных. DHCP и ARP дают IP и MAC; выбор сохраняется по MAC. IP-набор обновляется раз в 15 секунд, правила вставляются до перенаправления DNS и VPN. Старые соединения могут сохранять conntrack-маршрут до закрытия приложения; после смены приватного MAC устройство надо выбрать заново. При отсутствии сведений об IP выбранное устройство не добавляется в набор до обнаружения. Работа рассчитана на br0 и IPv4 LAN 192.168.50.0/24; IPv6 ранее отключён.
- RAM панели и Xray по RSS/Swap, доступная память системы, загрузка CPU между замерами, load average, свободное место /jffs, uptime и наличие USB.
- Журнал событий и последние записи автоконтроля, панели и обновления. Журналы ограничены и хранятся в RAM; UUID и VPN URI скрываются. На диск журнал постоянно не пишется.
- Смена пароля с проверкой текущего. Новый пароль 12–128 символов, соль и PBKDF2-SHA256; пароль открытым текстом не сохраняется. Старые сеансы завершаются, в том числе начавшие вход одновременно со сменой пароля.
- Экспорт/импорт JSON: группы, категории и устройства. Импорт сначала нормализуется и показывается как несохранённый; применение — отдельной кнопкой. Пароль и параметры сервера не экспортируются.
- Обновления через панель: ZIP до 8 МиБ, текущий пароль, проверка состава, SHA-256, размеров и архитектуры ELF; установка отдельным процессом, восстановление прежней программы/скриптов/состояния при неудачном запуске. После обновления нужен повторный вход. Краткий статус установки доступен без входа только из разрешённой LAN, чтобы пережить перезапуск сеанса. Сам пакет должен быть из доверенного источника: SHA-256 проверяет целостность, а не автора. На эту версию с 1.0.x нужен один ручной переход; следующие пакеты формата 1.1 можно ставить через интерфейс.

## Компактность и RAM

Установочный ZIP содержит только исполняемую программу, необходимые shell-скрипты и манифест. Исходники и материалы проверок вынесены в отдельный архив. Для уменьшения бинарника сборка отключает inlining Go и удаляет отладочные символы. Это компромисс размера и производительности управляющей панели; Go-тесты проходят с теми же флагами. Сам Xray не пересобирается.

Сохранены целевой мягкий бюджет Go 24 МиБ, ранняя сборка мусора и один исполнитель. Фактический RSS может превышать бюджет и не обязан стать ниже при простое. Опрос интерфейса раз в 30 секунд только в видимой вкладке, без наложения запросов. Следить за устройствами панель продолжает в фоне раз в 15 секунд, меняя наборы только при изменении IP/режима. Данные журналов и установочные файлы в /tmp используют RAM; успешный установщик удаляет известные временные пакеты, резервные копии в /jffs сохраняет.

## Первый переход на 1.1.0

Сохраните DARKLS-VPN-Panel-v1.1.0.zip в Downloads. Закройте панель на время обновления, чтобы не запускать применение одновременно с установкой.

PowerShell на Windows:

    Expand-Archive "$env:USERPROFILE\Downloads\DARKLS-VPN-Panel-v1.1.0.zip" "$env:USERPROFILE\Downloads\DARKLS-VPN-Panel-v1.1.0" -Force
    cmd /c 'tar -C "%USERPROFILE%\Downloads\DARKLS-VPN-Panel-v1.1.0" -cf - darkls-panel-update | ssh DARKLS@192.168.50.1 "tar -xf - -C /tmp"'

SSH на роутере:

    sh /tmp/darkls-panel-update/install-update.sh
    /jffs/xray/panel/darkls-panel --version
    /jffs/xray/panel/darkls-panel --check-vpn

Обновите http://192.168.50.1:8088 через Ctrl+F5. Текущий пароль сохраняется. Смена пароля, импорт/экспорт и дальнейшие обновления — в «Настройках». Восстановление списка — в «Резервных копиях». USB-флешка по-прежнему нужна для автозапуска. Если штатный firewall позже пересоздаст правила, монитор восстановит их вместе с политикой устройств.

## Обновления через интерфейс

«Настройки → Обновить панель», выбрать компактный runtime ZIP формата 1.1, ввести текущий пароль, нажать «Проверить и установить». ZIP с исходниками для установки не подходит. Более старая версия отклоняется; повторная установка той же версии допустима. При потере связи интерфейс проверяет состояние до трёх минут; если ожидание закончилось, обновите страницу и проверьте версию/журнал. Не отправляйте повторно пакет, пока предыдущая установка выполняется.

Предыдущий бинарник: /jffs/xray/panel/darkls-panel.previous. Снимок скриптов и состояния до последней установки: /jffs/xray/panel/update-rollback. При неудачном запуске установщик пытается вернуть их и проверить старую панель; если это не удалось, потребуется SSH и журнал /tmp/darkls-panel.log. Исходные параметры Xray при обновлении не меняются. Установка сначала проверяет наличие незавершённого журнала применения и останавливается, если нужно его восстановить.

## Границы маршрутизации

Работа зависит от DNS роутера; защищённый DNS браузера может обходить отбор. Для нового сайта со старым кешем устройства может потребоваться `ipconfig /flushdns` в Windows и перезапуск браузера. Выключенная группа больше не добавляет новые IP, но ранее определённые IP могут оставаться в VPN до 24 часов, в том числе из-за общих CDN. Очистка DNS на ПК сама по себе не удаляет ipset. Для немедленного полного отключения служит общий выключатель VPN.

Звонки/игры по прямым IP могут требовать дополнительных сетей. Каталог РКН — подборка, а не полный реестр; источники в CATALOG_SOURCES.md. Группы 18+ добавлены по запросу пользователя, новые выключены; состав в ADULT_DOMAINS_SOURCES.md не является утверждением, что все домены заблокированы. Политика устройств меняет маршрутизацию, а не служит системой идентификации или запрета доступа.

## Сборка и проверки

Нужен Go 1.27.2 и Python 3. Исполняемые зависимости на роутере прежние: sh, iptables/ipset, dnsmasq и стандартные средства прошивки. Python/Node на роутер не устанавливаются.

    GO_BIN=/path/to/go python3 build_release.py --version 1.1.0 --arch arm64 --output-dir dist
    go test -race ./...
    go test -gcflags=all=-l ./...
    go vet ./...

Для браузера: собрать `go test -c`, запустить TestBrowserHarness с DARKLS_BROWSER_PREVIEW=1 на 127.0.0.1:18088 и выполнить browser-test.cjs, затем на свежем harness — browser-features.cjs (нужны Playwright/Chromium в тестовой среде).

Проверены сохранение маршрутов при изменении групп, смена пароля и отзыв сеансов, импорт без применения, категории, DHCP/ARP и переиспользование IP, порядок правил включения/исключения устройств, диагностический DNS-запрос, парсинг CPU/RAM, целостность/пути/версии ZIP, неудачный запуск с возвратом бинарника/состояния/скриптов. Отдельный интеграционный тест провёл настоящий HTTP multipart upload, отдельный worker, остановку старого сервера, запуск сборки 1.1.1 и вход с сохранённым паролем. Это тестовый экземпляр с подменой роутерных путей/данных, не проверка ASUS. Интеграционные сценарии из integration запускайте только в изолированной Linux-среде без рабочей панели: они используют /tmp/darkls-panel.pid и локальные порты. Последняя проверка на реальном роутере — после установки.
