# DARKLS VPN Panel

**Выбор сайтов и устройств для домашнего VPN на ASUS TUF-BE6500.**

Локальная панель управляет существующей установкой Xray: маршруты, DNS, диагностика, восстановление, резервный канал и обновления. Работает в домашней сети, без облачного аккаунта и GitHub-токена на роутере.

[Скачать выпуск](https://github.com/iamdarkls/DARKLS-VPN-Panel/releases/latest) · [Архитектура](docs/ARCHITECTURE.md) · [Проверки CI](https://github.com/iamdarkls/DARKLS-VPN-Panel/actions)

> Это панель для **уже настроенного VPN**, а не прошивка и не установщик VPN с нуля. Она не содержит подписку, серверные ключи или персональный конфиг.

## Возможности

| Раздел | Что умеет |
| --- | --- |
| Сайты и сервисы | Группы доменов, категории, поиск, предпросмотр изменений, временное включение |
| Устройства | Вся сеть, только выбранные устройства или исключения; привязка к MAC |
| Связь | Отдельные проверки интернета, сервера, DNS, правил и HTTPS через VPN |
| Сервисы | Проверка известных зависимостей, различение DNS/TLS/HTTP/Cloudflare, история состояния |
| QUIC и XHTTP | QUIC по группам, временный режим TCP, изолированное сравнение XMUX, тест под нагрузкой |
| Восстановление | Раздельный запуск DNS, правил и Xray; проверяемый резервный канал |
| Обновления | Подписанные выпуски панели; официальные стабильные ядра и пререлизы Xray с USB-копией и откатом |
| Хранилище | Список копий, ручное удаление и безопасная автоочистка лишних файлов старше недели |
| Безопасность | Пароль, защита запросов, доступ из LAN, отчёт с удалением известных секретов |

## Совместимость

Проверяемая конфигурация проекта:

- ASUS **TUF-BE6500**, Linux **aarch64**, штатная прошивка с SSH;
- Xray в `/jffs/xray`, существующие `vpn.sh`, `watch.sh` и конфигурация;
- LAN `192.168.50.0/24`, интерфейс `br0`, панель `192.168.50.1:8088`;
- dnsmasq с ipset, iptables с TPROXY и существующий USB-автозапуск;
- флешка **WINDOWS_10** для текущего механизма автозапуска и постоянного отката ядра.

Другие модели, подсети и схемы запуска требуют адаптации. Xray работает из JFFS; его прежняя версия сохраняется на USB. Нельзя рассчитывать на автоматический откат без исправной подключённой флешки.

## Обновить панель

1. Открыть [панель](http://192.168.50.1:8088) → **Настройки → Проверить обновления**.
2. Выбрать **Установить проверенный выпуск** и ввести текущий пароль.
3. Дождаться завершения, войти повторно и обновить страницу через **Ctrl+F5**.

Пароль, выбранные сайты, устройства и реквизиты VPN сохраняются. Обновление панели само по себе не обновляет ядро Xray.

Запасной способ: скачать `DARKLS-VPN-Panel-v<версия>.zip` из Releases и загрузить его в разделе ручного обновления. **Архив Xray в это поле не подходит.** Для ручного ZIP необходимо доверять источнику: внутренний SHA-256 подтверждает целостность, но не автора.

### Первое подключение собственного GitHub

Для существующей старой панели используется первоначальный Windows-комплект `DARKLS-VPN-GitHub-Setup-v1.2.0.zip` и его `Publish-GitHub.ps1`. Он закрепляет публичный ключ репозитория и настраивает подпись выпусков. Первый выпуск устанавливается вручную; затем доступны обновления из панели. Это отдельная процедура, не установка VPN с нуля.

## Обновления Xray

**Настройки → Обновления ядра Xray.**

| Режим | Поведение |
| --- | --- |
| Автопроверка | По умолчанию включена. Проверка официальных выпусков и пререлизов раз в сутки |
| Установка по кнопке | Показывает версию и примечания; требует пароль и подтверждение |
| Автоустановка | По умолчанию выключена. Выполняется в выбранный час **МСК** при свежей успешной проверке VPN и подключённой USB |

Источник — только [`XTLS/Xray-core`](https://github.com/XTLS/Xray-core/releases). Среди 30 последних опубликованных выпусков, включая пререлизы, выбирается наибольшая числовая версия с Linux ARM64-архивом. Черновики пропускаются. В панели отдельно показан тип выпуска. Это относится и к автоустановке, если она включена. Автоматическое понижение версии запрещено, даже если GitHub предлагает выпуск старше установленного.

Порядок установки:

1. Скачать архив **на USB**, проверить размер и официальную SHA-256 из GitHub API или `.dgst`.
2. Распаковать только `xray`, проверить ELF/ARM64, версию и совместимость текущего конфига.
3. Сохранить и проверить прежнее ядро на USB, записать журнал отката в JFFS.
4. Заменить ядро и перезапустить Xray; DNS helper и правила при обычном успешном обновлении сохраняются.
5. Проверить DNS, правила и HTTPS через VPN. При ошибке попытаться восстановить прежнее ядро.

Неудачный выпуск блокируется для автоматических повторов. В интерфейсе можно явно разрешить ручной повтор. За ночь выполняется не больше одной автоматической попытки. Для ручного возврата есть кнопка **«Вернуть предыдущее ядро с USB»**.

Временно оборвутся существующие VPN-соединения. Короткая проверка не гарантирует длительную стабильность XHTTP: после обновления стоит проверить свои приложения. SHA-256 ядра берётся из официального HTTPS-источника; это отдельная проверка, **не Ed25519-подпись панели**.

## Автоочистка через неделю

По умолчанию включена; настройка находится в **Резервных копиях**. Первый обход — через две минуты после запуска панели, последующие — каждые шесть часов.

Удаляются известные лишние снимки, прежние ядра и временные файлы проекта **старше семи дней**. Сохраняются:

- текущие программы, пароль, VPN-конфиг, ключи и USB-загрузчик;
- последняя копия панели и последний снимок настроек;
- последняя копия ядра и копия, на которую указывает действующий откат;
- файлы активной операции и данные, необходимые для незавершённого восстановления.

Неизвестные файлы и содержимое соседних папок не удаляются. Символические ссылки не обходятся. При несинхронизированных часах очистка откладывается; даты из периода до синхронизации не используются для автоматического удаления. Свежий файл внутри старой папки также сохраняет папку.

История настроек дополнительно ограничена последними 12 снимками, поэтому при частых изменениях самые старые могут удаляться раньше недели. Журналы в RAM ограничиваются размером независимо от недельной очистки.

## Как работают маршруты

Домены включают поддомены. DNS роутера наполняет IP-наборы групп, после чего выбранный трафик направляется через Xray. Защищённый DNS браузера может обходить этот механизм. Общие CDN-IP могут использоваться несколькими сервисами: активная группа сохраняет нужный ей VPN-маршрут.

Изменение списка обычно не перезапускает Xray. Уже открытое соединение может сохранить прежний маршрут, а ранее найденный IP удалённого домена — остаться в кеше до 24 часов. Для проверки нового правила перезапустите приложение и очистите его DNS-кеш.

Запрет QUIC по умолчанию включён только у YouTube. Пробный режим и временное включение группы возвращают прежний выбор после срока; для этого нужны запущенная панель и синхронизированные часы. Выключенный роутер обработает истёкшие таймеры после следующей загрузки.

## Диагностика и резерв

В разделе **«Связь и восстановление»** доступны отчёт о сбое, проверки зависимостей, история сервисов, сравнение XHTTP и ограниченный тест задержки под нагрузкой. Ответ Cloudflare, HTTP-ошибка или отказ одного сайта не запускают полный перезапуск VPN.

Отчёт исключает сырой конфиг, пароль и известные поля с ключами/адресом VPN-сервера. IPv4 и MAC заменяются метками. В отчёте остаются выбранные проверки и последние ошибки; перед публичной публикацией проверьте свободный текст сторонних сообщений.

Резерв добавляется в **Настройках**: второй VLESS-профиль или один outbound JSON. Он проверяется отдельным Xray перед сохранением и переключением. Автопереключение выключено до явного включения; автоматического возврата на основной канал нет. Независимость серверов обеспечивает пользователь.

Замеры выполняются с роутера и не заменяют проверку браузера, приложения или Wi-Fi. XHTTP сравнивается в отдельном процессе с запасом не менее 96 МиБ доступной RAM. Короткая нагрузка ограничена 8 МиБ и 8 секундами; настройки QoS ASUS автоматически не меняются.

## Разработка и выпуски

**Go 1.27.2**, Python 3. Внешних Go-модулей и фронтенд-сборщика нет.

```sh
go test -race ./...
go vet ./...
python3 build_release.py --version 1.4.4
```

Подписанный выпуск создаётся после изменения `release-version.txt` и отправки коммита в `main`. GitHub Actions выполняет проверки, собирает ARM64 ZIP, подписывает метаданные и создаёт Release на проверенном коммите. Версии и опубликованные теги не перезаписываются.

Приватный ключ подписи находится в Actions secret `RELEASE_SIGNING_KEY`; в репозитории и бинарнике панели хранится только публичный ключ. На роутер GitHub-токен и приватный ключ не передаются.

Проверки проекта включают Go race/vet, тесты метаданных/архивов/таймеров/очистки/отката, браузерные сценарии и имитацию установщика. **Реальная установка нового ядра, скорость и длительная стабильность проверяются на ASUS.**
