# DARKLS VPN Panel

Локальная панель для уже настроенного ASUS TUF-BE6500 arm64: Xray/XHTTP/Reality, выбор сайтов и устройств, DNS/ipset, мониторинг и подписанные обновления GitHub Releases.

Это надстройка над существующей установкой VPN. Панель не содержит VPN-подписку, серверный конфиг или учётные данные. Не является прошивкой и не устанавливает VPN с нуля.

## Первое подключение GitHub Releases

1. Распаковать полный архив `DARKLS-VPN-GitHub-Setup-v1.2.0.zip` на Windows. Нужны Git, GitHub CLI (`gh`) и PowerShell 7. При необходимости: `winget install --id Git.Git --exact` и `winget install --id GitHub.cli --exact`; после установки открыть новый PowerShell.
2. Запустить `Publish-GitHub.ps1` из корня распакованного архива. Скрипт проверит аккаунт `iamdarkls`, создаст публичный `iamdarkls/DARKLS-VPN-Panel`, настроит секрет подписи, отправит исходники; GitHub Actions соберёт выпуск и создаст тег `v1.2.0`. При необходимости GitHub попросит войти в браузере и разрешить доступ к репозиториям/workflows.
3. Дождаться зелёного workflow **Publish signed panel release** во вкладке Actions. Первый выпуск скачать из Releases: `DARKLS-VPN-Panel-v1.2.0.zip`.
4. Один раз установить первый ZIP через существующую панель → Настройки → обновление. В этой сборке уже закреплён публичный ключ своего репозитория.
5. Следующие выпуски проверяются раз в сутки; в Настройках можно проверить вручную и установить по кнопке с текущим паролем. Автоустановки нет.

Для нового релиза: внести/проверить изменения, изменить `release-version.txt`, например на `1.2.1`, и отправить коммит в main. Workflow после тестов соберёт arm64 ZIP, подпишет метаданные Ed25519, создаст тег на точном проверенном коммите и опубликует Release. Версия должна иметь вид `ЧИСЛО.ЧИСЛО.ЧИСЛО` и увеличиваться; опубликованные теги не перезаписывать. Исходная `main.version` используется локально, версия выпуска задаётся из `release-version.txt` при сборке. Обычные коммиты без изменения этого файла не выпускают новую версию.

## Ключ подписи

- Приватный ключ создаётся **на Windows**, в `%USERPROFILE%\.darkls-vpn-signing\release-signing.key`, и передаётся командой `gh secret set` в Actions secret `RELEASE_SIGNING_KEY`. В исходники и ZIP панели не входит. Сохранить его резервную копию в своём защищённом хранилище.
- В `github-public-key.txt` хранится только публичный ключ. Первоначальное значение `UNCONFIGURED` означает, что сборка не может устанавливать GitHub-обновления. Публикационный скрипт заполняет ключ перед первым коммитом.
- Утрата/смена приватного ключа требует отдельной процедуры смены доверия; новый случайный ключ нельзя незаметно подменить обычным повторным запуском.
- Права записи в репозиторий и Actions secrets означают доверие выпускать обновления: не выдавать их посторонним.
- GitHub CLI использует свою авторизацию на ПК. Роутеру GitHub-токен не нужен.

## Проверки и откат

GitHub-путь проверяет Ed25519-подпись исходных байтов `panel-release.json`, владельца/репозиторий, вид пакета, версию, архитектуру, имя, размер и SHA-256 ZIP. Затем повторно проверяет внутренний манифест и файлы. Пакеты старее текущей версии, prerelease/draft и несовпадающие теги не устанавливаются. Установщик использует резервную копию и пытается вернуть прежнюю панель при отказе запуска. Ручная загрузка ZIP сохранена как запасной способ; для неё по-прежнему требуется доверять источнику файла.

Загрузка использует HTTPS с Mozilla CA bundle; сначала напрямую, затем через локальный SOCKS Xray. Входящие соединения панели остаются только в LAN. Ключи/пароль/группы/адрес сервера не отправляются в GitHub. Первый выпуск нужно вручную получить из своего репозитория и установить; это начальное закрепление доверия.

**Ядро Xray не меняется при обновлении панели.** У него отдельная операция с резервной копией на USB; текущая версия поддерживает проверенный переход на 26.10.10. Автоматическое обновление произвольных будущих ядер в этот выпуск не входит.

## Сборка и тесты

Go 1.27.2, Python 3; внешних Go-модулей нет.

```sh
go test -race ./...
go vet ./...
python3 build_release.py --version 1.2.0
```

Подробности текущей конфигурации роутера и старых миграций: [README_RU.md](README_RU.md). Пакет рассчитан на `/jffs/xray`, `br0`, LAN `192.168.50.0/24`, адрес панели `192.168.50.1:8088` и настроенный USB-автозапуск. Проверен локально; установку нового выпуска необходимо проверить на реальном ASUS.
