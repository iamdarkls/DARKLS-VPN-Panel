# DARKLS VPN Panel

Локальная панель управления Xray на **ASUS TUF-BE6500**. Выбирай сервисы и устройства для VPN, сохраняй серверы, проверяй связь и устанавливай обновления из браузера.

[Скачать выпуск](https://github.com/iamdarkls/DARKLS-VPN-Panel/releases/latest) · [Руководство](docs/USER_GUIDE.md) · [Разработка](docs/DEVELOPMENT.md) · [Проверки](https://github.com/iamdarkls/DARKLS-VPN-Panel/actions)

## Совместимость и установка

Пакет предназначен для **существующей установки панели и Xray**. Он не настраивает VPN с нуля и не содержит серверов, подписок или ключей.

| Требование | Текущая конфигурация |
| --- | --- |
| Роутер | ASUS TUF-BE6500, Linux ARM64 (`aarch64`), штатная прошивка с SSH |
| VPN | `/jffs/xray`: Xray, `config-vpn.json`, `vpn.sh`, `watch.sh` |
| Маршрутизация | dnsmasq с ipset, iptables с TPROXY |
| Домашняя сеть | `192.168.50.0/24`, интерфейс `br0` |
| Веб-панель | [192.168.50.1:8088](http://192.168.50.1:8088) |
| USB | Флешка `WINDOWS_10` для текущего автозапуска и постоянной копии ядра |

Панель и Xray запускаются из JFFS; флешка используется для автозапуска и отката ядра. Другие роутеры, подсети и загрузчики требуют адаптации. HTTP-доступ рассчитан на доверенную домашнюю сеть. Облачный аккаунт и GitHub-токен на роутере не нужны.

### Обновление существующей панели

1. Открой **Обновления → Панель · GitHub → Проверить обновления**.
2. Выбери **«Установить проверенный выпуск»** и введи пароль панели.
3. Дождись завершения, войди повторно и обнови страницу через **Ctrl+F5**.

Пароль, сайты, устройства и параметры VPN сохраняются. Обновление панели не обновляет Xray.

Для ручной установки скачай `DARKLS-VPN-Panel-v<версия>.zip` из [Releases](https://github.com/iamdarkls/DARKLS-VPN-Panel/releases) и открой **Обновления → Установка из ZIP**. Архив Xray в это поле загружать нельзя. GitHub-обновление проверяется по Ed25519-подписи; ручной ZIP — по составу и SHA-256, поэтому используй доверенный источник.

Канал панели по умолчанию **стабильный**, установка — по кнопке. Канал «Стабильный + тестовый» включает предварительные выпуски. Возврат с тестовой версии выполняется через стабильный канал и кнопку **«Вернуться на стабильный выпуск»** после проверки; обычный ZIP не разрешает понижение версии.

## Основные действия

### Выбрать сайты и устройства

В **«Сайты и сервисы»** включи нужные группы. В **«Устройства»** выбери всю сеть, отдельные устройства или исключения. Открой предпросмотр и примени изменения. Для каждой группы доступна настройка QUIC; временное включение возвращает прежний выбор по таймеру.

Маршрутизация использует DNS роутера и IP-наборы. Защищённый DNS браузера может обходить этот механизм, а общий IP CDN — затрагивать соседние сервисы. Открытые соединения могут сохранять прежний маршрут: после изменения перезапусти приложение. Ранее найденные IP могут оставаться в наборе до 24 часов.

### Подключить сервер или подписку

В **«VPN-серверы»** можно сохранить до 20 серверов через VLESS-ссылку, outbound JSON или ручной ввод. Сохранение и подключение — отдельные действия. Резервный канал находится на собственной вкладке.

Для HTTPS-подписки:

1. Вставь ссылку, введи пароль панели и нажми **«Загрузить профили»**. Для сохранённой ссылки поле можно оставить пустым.
2. Выбери узел и нажми **«Сохранить и привязать»**.
3. Нажми **«Проверить подписку»**, просмотри изменения и отдельно подтверди применение.

Загрузка списка не переключает VPN. Поддерживаются текстовые и Base64-списки VLESS с REALITY или проверяемым TLS. В списке из нескольких узлов нужны уникальные имена. HTML, JSON-подписки и переадресации не принимаются. Автообновление подписки включается отдельно; при переходе на резерв или ручной смене основного профиля привязку нужно проверить заново.

### Обновить ядро Xray

Открой **Обновления → Ядро Xray**. Доступны официальные стабильные выпуски и пререлизы [XTLS/Xray-core](https://github.com/XTLS/Xray-core/releases).

Автопроверка включена, автоустановка изначально выключена. Для автоустановки задаются час **МСК** и отсрочка после публикации: по умолчанию 3 суток, допустимо 0–30. Перед заменой сохраняется ядро на USB и проверяются конфигурация и туннель; при ошибке выполняется откат. VPN-соединения при замене переподключаются.

## Если связь пропала

В **Контроль связи → История связи** открой **«Почему VPN не работает»**: там показаны результаты проверок прямого HTTPS, TCP сервера, VPN, DNS и правил. Над разделами отображается выполняемая операция. Ручные действия могут прервать фоновую проверку; установка ядра и восстановление должны завершиться.

- **Диагностика** проверяет сервисы, их зависимости и ожидаемый маршрут, а также формирует отчёт о сбое. Ответ Cloudflare не подтверждает вход в аккаунт.
- **Журналы** открываются в отдельном окне: источник, поиск, уровень записей, скачивание и автообновление. Закрытие окна останавливает опрос.
- **Контроль связи → Восстановление** позволяет завершить незавершённый откат. Если требуется прежнее ядро, подключи исходную USB-флешку. Не удаляй журналы отката вручную.
- При недоступности прежнего VPN-сервера можно завершить откат подключения с выключенным VPN, затем выбрать рабочий сервер. Подробности и ограничения: [команды и восстановление](docs/ADMIN.md).

Отказ одного сайта не должен вызывать полный перезапуск VPN. Для продолжительных обрывов и проверки нескольких клиентов используй [методику проверки стабильности](docs/ROUTER_SOAK.md). Стенд CI не воспроизводит прошивку ASUS, Wi-Fi и линию провайдера.

## Остальные возможности

| Раздел | Возможности |
| --- | --- |
| Настройка связи | Пробный QUIC/TCP, сравнение XHTTP и задержка под нагрузкой |
| Копии и файлы | Снимки, импорт/экспорт, известные установочные файлы и недельная очистка |
| Ресурсы роутера | CPU, доступная RAM, RSS процессов, место в JFFS и USB |
| Пароль панели | Смена пароля с завершением прежних сеансов |

Очистка удаляет известные лишние файлы старше недели и сохраняет последние копии для отката. Журналы ограничены размером и хранятся в RAM до перезагрузки. Подробности: [руководство пользователя](docs/USER_GUIDE.md).

Интерфейс поддерживает светлую и тёмную темы, сворачиваемое меню и уведомления снизу справа. Анимации учитывают системную настройку уменьшенного движения.

## Разработка

**Go + Vue 3 + TypeScript + Vite.** На роутере работает один Go-бинарник со встроенными сжатыми ресурсами. Node.js нужен только для разработки и CI; интерфейс не загружает дизайн-фреймворки или шрифты с CDN.

| Каталог | Назначение |
| --- | --- |
| `cmd/darkls-panel/` | Точка запуска |
| `internal/panel/` | HTTP API, компоненты VPN и тесты |
| `internal/routerenv/`, `internal/routerexec/` | Сетевой контракт и запуск утилит с тайм-аутами |
| `web/src/` | Vue-компоненты, composables, состояние и API-клиент |
| `assets/` | Публичный ключ подписи и корневые сертификаты |
| `tests/`, `tools/` | Интеграционные проверки, сборка и подпись |
| `release/`, `router/` | Обновление и обслуживание роутера |
| `docs/`, `bench/` | Руководства и измерения |

Начни с [разработки и сборки](docs/DEVELOPMENT.md). Устройство компонентов описано в [архитектуре](docs/ARCHITECTURE.md), источники доменов — в [каталоге сервисов](docs/catalog/SERVICES.md) и [дополнительном каталоге](docs/catalog/ADULT.md). Измерения размера и памяти находятся в [bench](bench/README.md).

История изменений публикуется в [GitHub Releases](https://github.com/iamdarkls/DARKLS-VPN-Panel/releases).
