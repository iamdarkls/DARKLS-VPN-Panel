# Память панели: локальный микротест

Проверяет пиковый RSS Linux-процесса через `wait4`, три запуска на сборку, по 1200 авторизованных запросов к state/export/backups. Одинаковые Go 1.27.2, флаги сборки и каталог сайтов. Тест не создаёт VPN-трафик и не измеряет RSS ASUS ARM64.

```sh
cc -O2 -Wall -Wextra -o bench/rss-supervisor bench/rss-supervisor.c
DARKLS_BASELINE_BINARY=/path/to/baseline DARKLS_OPTIMIZED_BINARY=/path/to/current python3 bench/memory.py
```

Результат записывается в `bench/results.json`. Сборки должны быть Linux amd64 и находиться вне работающей установки VPN. Используются loopback 18089 и временные файлы `/tmp/darkls-panel.pid`.

Сравнение 1.3.0 → 1.4.0: медианы пикового RSS **12 984 → 13 268 КиБ**; отдельные прогоны 12 736–13 116 и 13 020–13 348 КиБ. Это около 13 МиБ в обоих случаях, снижение общего RSS не подтверждено. В 1.4.0 добавлены новые фоновые функции; устранение повторного разбора CA и создание таблицы API один раз уменьшают повторную работу, но этот HTTP-тест не измеряет TLS-проверки. Для выводов о реальном роутере нужны его метрики.

## Разбор метаданных Xray: 1.4.1 → 1.4.2

```sh
go test ./internal/panel -run '^$' -bench BenchmarkCoreMetadata -benchmem -count=3
```

Одинаковый синтетический JSON из 30 выпусков с длинными примечаниями. Медиана суммарных выделений на один разбор: **6 400 422 → 2 119 524 байта**, примерно на 67% меньше. Потоковый путь не создаёт копию всего ответа и полный массив выпусков. Число отдельных выделений выросло со 102 до 232; выигрыш относится к объёму выделяемых данных.

Это локальный тест Go на Linux amd64, не измерение общего RSS роутера. Постоянное потребление RAM и пропускная способность VPN этим результатом не подтверждаются. Тест `TestMaintenanceSkipsProcessScanForUnchangedDevicePolicy` отдельно проверяет отсутствие внешних команд и входа в межпроцессную блокировку при неизменившейся политике устройств.

## Компактная раздача UI и валидация: 1.8.0 → 1.8.1

[Исходные результаты всех прогонов](optimization-1.8.1.json). Go 1.27.2, Linux amd64, одинаковые компактные флаги с `-gcflags=all=-l`; три последовательных прогона на вариант, медианы. Для размера бинарника и ZIP использована реальная ARM64-сборка.

| Измерение | До | После |
| --- | ---: | ---: |
| ARM64-бинарник | 7 602 300 байт | 7 340 156 байт |
| ZIP обновления | 2 978 518 байт | 2 951 160 байт |
| Тела HTML/JS/CSS при первой загрузке | 151 354 байта | 46 049 байт с gzip |
| Нормализация домена | 1 087 нс | 251,4 нс |
| Выделения при нормализации | 132 байта, 2 выделения | 88 байт, 1 выделение |
| Чтение и проверка state.json | 480 938 нс | 320 462 нс |
| Выделения при чтении state.json | 98 432 байта, 1 155 выделений | 89 887 байт, 937 выделений |
| 1 200 HTTP-запросов state/export/backups | 0,823 с | 0,730 с |
| Пиковый RSS в том же HTTP-тесте | 13 204 КиБ | 12 980 КиБ |

Бинарник меньше на **256 КиБ**, архив — на **27 358 байт**. Первичная передача интерфейса меньше примерно на **70%**; повторная проверка неизменённого JS/CSS возвращает 304 без тела. Нормализация быстрее примерно в 4,3 раза, чтение/валидация состояния — на 33%, HTTP-серия — на 11% в этом локальном тесте.

RSS исходной версии: 12 872–13 208 КиБ; новой: 12 696–13 016 КиБ. Диапазоны пересекаются: **существенное снижение общей RAM не подтверждено**. Объём выделений на операцию и пиковый RSS — разные величины. Скорость Xray, Wi-Fi и поведение реального ASUS этим тестом не измерялись.

Обычная сборка с встраиванием функций отдельно дала ARM64-бинарник 8 323 196 байт вместо 7 602 300. Она не выбрана: приоритет компактного выпуска сохранён. Полный набор корневых сертификатов и проверки здоровья VPN не сокращались.

Воспроизведение микротестов для каждого checkout:

```sh
go test -gcflags=all=-l ./internal/panel -run '^$' -bench 'Benchmark(NormalizeDomain|StateRead)$' -benchmem -count=3
```

Для старой версии скопируй в её checkout только `internal/panel/performance_test.go`: функции теста одинаковые, код нормализации и состояния остаётся старым. Для HTTP/RSS используй одинаковые Linux amd64-сборки и команду из начала документа.
