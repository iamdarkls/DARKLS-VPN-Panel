# Архитектура

## Компоненты

| Каталог | Ответственность |
| --- | --- |
| `cmd/darkls-panel/` | Точка запуска Go |
| `internal/panel/` | HTTP API, авторизация, состояние, транзакции, монитор и обновления |
| `internal/routerenv/` | Фиксированный сетевой контракт поддерживаемой установки |
| `internal/routerexec/` | Запуск утилит с ограничением времени и ожидания унаследованных pipes |
| `web/src/views/` | Vue-компоненты разделов панели |
| `web/src/components/` | Диалоги, уведомления, вкладки, таблицы и общие элементы |
| `web/src/composables/` | Периодические задачи, тема, уведомления и операции UI |
| `web/src/api.ts`, `types.ts` | HTTP-клиент, отмена запросов и типы ответов API |
| `web/src/store.ts` | Сеанс, черновик маршрутов, ревизия и общий статус |
| `web/src/outbound.ts` | Типизированное чтение/изменение известных полей outbound |
| `tools/`, `release/`, `router/` | Сборка, подпись и shell-интеграция |

На роутере работает один Go-бинарник панели. Vue выполняется в браузере; Vite и TypeScript работают при сборке. CDN и серверный Node.js не используются. Компактный OTA-контракт из шести файлов сохранён.

## Интерфейс

`App.vue` владеет навигацией, общим состоянием загрузки, авторизацией и панелью применения. Реестр `navigation.ts` задаёт разделы и вкладки. `v-show` сохраняет экземпляры экранов и незавершённые формы между переходами; выход из сеанса размонтирует авторизованное дерево целиком.

Обновляется только текущий раздел и выбранная вкладка. При переходах во время медленного ответа ставится один повтор для последнего назначения. Профили серверов не загружают настройки монитора. Автоопрос видимой панели и отдельный опрос активного задания Xray не накапливают очередь запросов.

`store.ts` хранит редактируемый список отдельно от исходного снимка. Предпросмотр захватывает копию черновика и ревизию; применяется именно эта копия. Отмена возвращает сохранённый снимок. Политика устройств и группы применяются одной транзакцией API.

API-клиент отправляет cookie и CSRF, ограничивает время запроса и локализует ошибки. При завершении сеанса все его запросы отменяются; номер поколения проверяется до и после разбора ответа. Поздний ответ прежнего сеанса не может раскрыть сервер, заменить новый черновик или повторно открыть диалог.

Пароли, URI и outbound находятся только в оперативном состоянии компонентов. Закрытие редактора, успешное действие и выход очищают соответствующие поля. В localStorage сохраняются только тема, отметка прочитанного уведомления и одноразовое сообщение о завершении обновления.

## Серверы и уведомления

`ServersView.vue` содержит карточки сохранённых серверов, редактор и подтверждения паролем. GET передаёт только метаданные. Раскрытие реквизитов, переключение и удаление требуют защищённого POST. Переименование не проверяет канал и не перезапускает VPN; сохранение копии и подключение остаются отдельными действиями.

`outbound.ts` клонирует исходный outbound и меняет только известные поля. Дополнительные XHTTP extra, XMUX, gRPC и sockopt не теряются. Для неподдержанного ручным редактором протокола остаётся полный outbound JSON. Конфигурацию окончательно проверяет Xray на серверной стороне.

Уведомления управляются Vue и ограниченной очередью. `Teleport` переносит область в открытый native dialog, чтобы top layer не скрывал ошибки; при закрытии возвращает её в body. Таймеры очищаются при размонтировании, ошибки остаются до закрытия. Удалённые значения выводятся как текст: `v-html`, eval и исполняемые inline-шаблоны не используются.

## Сборка и публичные ресурсы

Vite собирает `web/dist/index.html`, `assets/panel.js` и `assets/panel.css`. Python встраивает их в `assets_generated.go` в виде gzip-строк без постоянной распакованной копии. Он также сохраняет SHA-256 всех редактируемых Vue/TS/CSS и конфигурационных входов сборки. Изменение исходников без пересборки обнаруживается до упаковки выпуска.

Go раздаёт только точные ключи сгенерированной карты. JS/CSS получают ETag и обязательную перепроверку кеша; HTML и API — no-store. Для gzip передаются готовые байты, identity декодируется потоком, HEAD не распаковывает тело. Исходники `.vue`, TypeScript, node_modules и произвольные файлы недоступны по HTTP.

## Сеть и доверие

Панель принимает запросы из LAN/loopback с точным Host. POST дополнительно требует Origin и CSRF. Пароль хранится как salted PBKDF2-хеш; смена пароля завершает прежние сеансы. Удаление файлов ограничено известными копиями, пути из запроса не исполняются.

Выпуск панели проверяется закреплённым Ed25519-ключом, SHA-256 и внутренним манифестом. Официальный Xray загружается из XTLS/Xray-core по HTTPS с проверкой SHA-256 и ARM64 ELF. Архивы ограничены размерами, не извлекаются произвольные ZIP-пути. CA pool разбирается один раз.

`routerenv` задаёт текущие LAN, интерфейс, порты, метку и таблицу. Это контракт установки, а не автоматическое обнаружение другой сети. Legacy `vpn.sh` остаётся файлом роутера; его хуки подключают native-политику групп. Группы используют IP-наборы dnsmasq; атомарные swaps наборов и сменные body-цепочки уменьшают окно изменения правил. Клиентский DoH и общие CDN-адреса ограничивают точность отбора.

## Транзакции и восстановление

HTTP-изменения сериализуются `mutation`, CLI и фоновые операции — также файловой `apply.lock`. Для настроек, профиля и ядра используются отдельные журналы: запись журнала предшествует изменению, удаление выполняется после успешного завершения или проверенного отката. JSON записывается через временный файл, fsync и rename.

При незавершённом откате UI остаётся доступен для входа, отчёта и повторного восстановления. Изменения блокируются до завершения журнала. Переключение сервера сохраняет прежнюю конфигурацию и метаданные; проверяется кандидат отдельным Xray, затем рабочий канал. Неуспешный откат сохраняет журнал.

Для обновления ядра нужны USB-копия и свободное место с учётом размера кандидата и выделенных блоков прежнего бинарника. Автоустановка учитывает дату выпуска, отсрочку, час МСК, успешную проверку VPN и блокировку неудачной версии. Доступны стабильные выпуски и пререлизы; автоматического понижения нет.

## Владение автоконтролем

`Monitor` работает внутри serving-процесса только для штатного `/jffs/xray`; он владеет сериями отказов и монотонными интервалами. Диагностики делят один слот, восстановление берёт mutation и apply.lock. Во время обновления или незавершённой транзакции проверки пропускаются.

`watch.sh` контролирует запуск панели и heartbeat с PID и Linux uptime. Пауза более 240 секунд допускает перезапуск панели. Оставшийся после аварии каталог блокировки проверяется по прежнему владельцу. Watcher не запускает бинарник для каждой сетевой пробы и не перезапускает Xray сам.

| Задача | Приблизительный интервал |
| --- | --- |
| Структура и heartbeat | 15 секунд |
| Общий HTTPS | 30 секунд |
| Глубокая проверка правил и DNS, обслуживание журналов | Минута |
| DHCP-политика устройств и таймеры групп | 15 секунд |
| Известные сервисы | По умолчанию 5 минут на сервис, не более одного за цикл |
| Проверка выпусков панели и ядра | Сутки, после ошибки — час |
| Проверка окна автоустановки | 15 минут |
| Ресурсы | Минута |
| Недельная очистка | Через 2 минуты после старта, затем каждые 6 часов |

Следующий интервал отсчитывается после завершения. Команды, DNS, HTTP и ожидания делят родительский бюджет: правила — 8 секунд, правила с DNS — 20, связь — 45, отчёт — 60, цикл монитора — 60, восстановление — 90, итоговое подтверждение внутри него — до 45. Агрегатный тайм-аут означает неполную проверку, не доказанный отказ.

После действий подтверждаются оба DNS-входа, правила и HTTPS. Попытка, подтверждение и неудачное подтверждение различаются. Прежний успешный HTTPS не стирает отказ DNS: общий зелёный статус возвращается после полного успешного цикла. Нулевые, будущие и чужие PID/uptime heartbeat не считаются свежими.

## RAM, история и границы проверки

Журналы и история находятся в RAM и ограничены размером. Сводка за сутки отличает наблюдаемые интервалы от пропусков; перезагрузка очищает историю. Снимок до восстановления включает память, conntrack и последние ошибки без конфигурации, а отчёт дополнительно псевдонимизирует IP/MAC.

Очистка удаляет только известные старые файлы после синхронизации часов, сохраняя последние копии и данные незавершённых операций. Go memory limit мягкий; VSZ не равен потреблённой RAM. Vue не уменьшает RSS Xray и не устраняет ограничения удалённого VPN-сервера.

Браузерные проверки используют Go-harness; установочные — временные фикстуры; Linux network namespaces — настоящий NAT/DNS с тремя клиентами. Длительная стабильность прошивки ASUS и XHTTP требует [проверки на устройстве](ROUTER_SOAK.md).
