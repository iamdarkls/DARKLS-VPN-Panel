## Состояние и блокировки

Конфиг, пароль, выбор групп и настройки хранятся в JFFS. Временные результаты, история сервисов и журналы — в RAM. Прежние ядра и временная распаковка Xray — на USB.

HTTP-изменения используют `mutation`; действия отдельного CLI/монитора согласуются файловой блокировкой `apply.lock`. Долгие проверки не запускаются параллельно в диагностическом слоте. Для операций Xray есть отдельная блокировка и состояние задания. Загрузка выполняется при живом туннеле; файловая блокировка замены берётся перед проверкой и установкой ядра. Настройки в это время менять нельзя.

Запись JSON выполняется через временный файл, `fsync` и переименование. Для изменения настроек, переключения профиля и обновления ядра используются отдельные журналы. Незавершённый журнал блокирует конфликтующие операции и очистку. При перезапуске панели выполняется восстановление.

## Сеть и доверие

Панель проверяет адрес клиента, точный Host, сеанс, Origin и CSRF для POST. Смена пароля, установка, переключение профиля и удаление копий требуют текущий пароль. Удаление ограничено известными элементами; произвольный путь из запроса не исполняется.

Выпуски панели проверяются закреплённым Ed25519-ключом, затем SHA-256 и внутренним манифестом. Выпуски Xray загружаются из официального репозитория по HTTPS с проверкой SHA-256; это другой механизм доверия. Внешние диагностики используют фиксированные сервисы.

Список выпусков Xray разбирается потоком: в памяти остаётся выбранный выпуск, а не весь HTTP-ответ и массив релизов. Ограничение ответа 4 МиБ проверяется и при досрочном завершении обработчика. Оборванный JSON и данные после массива отклоняются.

Общий CA pool разбирается один раз и используется клиентами только для чтения. Архивы загружаются потоком; Xray распаковывается на USB с ограничением размера, без извлечения чужих путей из ZIP.

## Периодические задачи

| Задача | Период |
| --- | --- |
| Проверка процессов и подключений цепочек | Цикл монитора около 15 секунд |
| Общая HTTPS-проба | Около 30 секунд, с защитой от повторных восстановлений |
| Глубокая проверка правил и DNS | Около минуты |
| Обновление IP выбранных устройств и таймеры групп | Около 15 секунд |
| Проверка выбранных сервисов | По умолчанию 5 минут на сервис; не более одной пробы за цикл 15 секунд |
| Ограничение журналов | Один запуск обслуживания примерно раз в минуту |
| Проверка выпусков панели и Xray | Раз в сутки при доступности источника |
| Проверка окна автоустановки Xray | Каждые 15 минут, час задан в МСК |
| Замер RAM и RSS | Раз в минуту, журнал в RAM до 512 КиБ |
| Недельная очистка | Первый обход через 2 минуты, затем каждые 6 часов |

У каждого фонового задания один исполнитель. Следующий интервал отсчитывается после завершения операции: медленная сеть не создаёт очередь пропущенных запусков. Задания получают общий контекст отмены и запускаются только после успешного открытия HTTP-порта.

Проверки таймеров и устройств используют один цикл и одно чтение состояния. При неизменившейся политике и IP устройств цикл не входит в `pause` и не сканирует процессы. Перед реальным изменением набор вычисляется повторно под межпроцессной блокировкой.

Фоновая проверка сервиса пропускает цикл, если диагностический слот занят ручной проверкой или обновлением ядра. Отказ поиска обновлений повторно проверяется через час; успешный поиск — через сутки. Время проверки из будущего после коррекции часов не считается свежим.

Периоды приблизительные: длительность сетевых операций, занятую блокировку или несинхронизированные часы нельзя считать точным таймером. Сам по себе ответ одного сайта с ошибкой не вызывает перезапуск общего туннеля.

## Проверки

Go-тесты не требуют доступа к домашнему VPN. В них проверяются отказы, пределы, правила и журналы на временных файлах/заглушках. Браузерные проверки используют локальную тестовую панель; установочные сценарии имитируют роутер. ARM64-пакет проверяется по ELF и контрольным суммам.

Работоспособность на конкретной прошивке, транспорт под нагрузкой и длительная стабильность нового ядра требуют проверки на реальном устройстве. Локальные тесты не заменяют этот этап.

## Смена основного подключения

`connections.json` содержит не более 20 копий outbound, доступных для раскрытия только POST-запросом с паролем и CSRF. Смена сериализуется через `mutation`, диагностический слот и `apply.lock`. Временный Xray сначала проверяет кандидата без изменения рабочего конфига. Вывод кандидата не сохраняется: новые ключи ещё не входят в источники очистки журналов.

Журнал переключения фиксирует конфиг, метаданные активного профиля и прежние файлы primary/backup, включая их отсутствие. После проверки полного конфига заменяется только outbound `vpn`; проверяется рабочий туннель, затем сохраняется основной профиль. При ошибке возвращается снимок. Незавершённый откат сохраняет журнал и блокирует конфликтующие операции. `previous-connection.json` хранит один прежний конфиг для ручного возврата подключения; восстановление берёт только outbound, не заменяя текущие настройки остальных компонентов.

Сводка использует ограниченные JSONL-журналы проб и ресурсов в RAM. Проба описывает интервал до следующей, но не более 100 секунд; остальное считается неизвестным. Счётчик восстановлений отражает попытки, а не доказанную длительность простоя. Данные до синхронизации часов не записываются. Опрос уведомлений использует существующий цикл статуса и объединяет одновременные запросы.

Автообновление Xray учитывает `published_at`: стандартная отсрочка — 3 суток, диапазон 0–30. При неизвестной дате и ненулевой отсрочке автоматическая установка ждёт. Ручная установка её обходит. Запрет понижения, блокировка неудачных версий, час МСК, проверка туннеля и USB остаются обязательными.

## Интерфейс серверов и уведомления

`web/manage.js` содержит карточки серверов, отдельный редактор и подтверждения действий паролем. Чтение списка передаёт только метаданные; раскрытие реквизитов требует POST с паролем. Имя и ID редактируемой записи закрепляются при открытии окна, обновление списка не заменяет черновик. Закрытие очищает реквизиты. Переименование отдельным `connection-rename` не вызывает тест кандидата или перезапуск. `connection-snapshot` читает действующий outbound на роутере, проверяет и сохраняет новую копию без передачи ключей в браузер.

`web/notifications.js` управляет ограниченной очередью сообщений и историей в памяти вкладки. Область уведомлений переносится в открытый dialog, чтобы HTML top layer не скрывал ошибки; при закрытии возвращается в body. Уведомления не перехватывают фокус. Размер нижней панели отслеживается ResizeObserver, CSS учитывает reduced motion. Переходы VPN создают события, повторные одинаковые ошибки остаются только в журнале проб.
