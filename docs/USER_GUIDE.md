## Управление VPN-сервером

Открой раздел **«VPN-серверы»**. Вверху показано текущее подключение, ниже — карточки сохранённых серверов.

1. **«Добавить сервер»** → укажи название, вставь VLESS-ссылку или outbound JSON и введи пароль панели. Можно переключиться на ручной ввод; для просмотра импортированных полей есть **«Разобрать в ручные поля»**.
2. **«Проверить и сохранить сервер»** проверяет соединение отдельным Xray и сохраняет копию. Работающий канал остаётся прежним.
3. **«Подключить»** на карточке запрашивает пароль, проверяет сервер и полный конфиг, затем переключает основной outbound `vpn`. При ошибке выполняется откат. Текущий сервер отмечен **«Подключён»**.

**«Сохранить текущее в список»** создаёт копию действующего подключения без ручного копирования ключей. **«Изменить»** открывает параметры конкретной карточки; после сохранения нужно отдельно подключиться, чтобы применить их к VPN. **«Переименовать»** меняет только название и работает без проверки доступности сервера. **«Удалить»** удаляет копию из списка и не отключает работающий канал.

Хранится до 20 серверов. Расширенное действие в редакторе позволяет применить подключение без сохранения в список. Прежний сервер доступен через **«Вернуть предыдущее подключение»**. Резервный канал добавляется во вкладке **«Резервный канал»**. Его автопереключение включается отдельно в **Контроль связи → Автоконтроль**.

XHTTP `extra`, XMUX, HTTP-метод и неизвестные JSON-поля сохраняются при редактировании. Неизвестные параметры ссылки отклоняются: для них используйте JSON. При ошибке переключения восстанавливаются конфиг и оба профиля; незавершённый журнал отката сохраняется для восстановления при запуске панели.

Чтение ключей и действия требуют пароль. Реквизиты хранятся на роутере с правами `0600`, не попадают в обычный экспорт настроек или browser storage и очищаются при закрытии редактора или выходе. Доступ к панели по HTTP предназначен для доверенной LAN. Изолированной проверке нужно не менее 96 МиБ доступной RAM.

Для **gRPC** в редакторе доступны `serviceName`, отдельный `authority` и режим **Gun / Multi**. Ссылки поддерживают `authority`, `mode=gun|multi` и `multiMode=true|false`; противоречащие друг другу режимы отклоняются с пояснением. TLS ALPN задаётся отдельно, например `h2`. Если Xray сообщает об удалённом `allowInsecure`, панель показывает отдельное пояснение: проверка сертификата автоматически не отключается. Параметры сервиса, безопасности и порт должны соответствовать серверу; локальные тесты панели не доказывают доступность вашего внешнего сервера.

## Интерфейс и уведомления

Основной текст — 16 px, подписи и элементы меню — до 14–15 px, текст полей ввода — до 16 px, включая телефон.

Светлая и тёмная темы используют графитовую палитру с синим акцентом; выбранный режим сохраняется в браузере. Интерфейс не загружает внешние шрифты, UI-библиотеки или скрипты.

Сообщения появляются **снизу справа**, поверх страницы, в том числе внутри окон редактора. Успешные действия скрываются через 8 секунд; наведение мыши и фокус приостанавливают таймер. Ошибки и уведомления VPN остаются до закрытия. Одновременно показываются до трёх сообщений, в модальном окне — одно. Кнопка **«Уведомления»** открывает последние 30 сообщений этой вкладки. Они хранятся только в памяти браузера и очищаются при выходе.

Повторные пробы с той же ошибкой не создают новые события сбоя; полная история HTTPS-проб продолжает собираться. Новая причина ошибки и восстановление показываются отдельно. Панель применения снизу появляется при несохранённых изменениях и не перекрывается уведомлениями.

## Обновления Xray

**Обновления → Ядро Xray.**

| Режим | Поведение |
| --- | --- |
| Автопроверка | По умолчанию включена. Проверка официальных выпусков и пререлизов раз в сутки |
| Установка по кнопке | Показывает версию и примечания; требует пароль и подтверждение |
| Отсрочка | По умолчанию 3 суток после публикации, настраивается от 0 до 30 дней; действует на стабильные выпуски и пререлизы. Ручная установка доступна сразу |
| Автоустановка | По умолчанию выключена. Выполняется в выбранный час **МСК** при свежей успешной проверке VPN и подключённой USB |

Источник — только [`XTLS/Xray-core`](https://github.com/XTLS/Xray-core/releases). Среди 30 последних опубликованных выпусков, включая пререлизы, выбирается наибольшая числовая версия с Linux ARM64-архивом. Черновики пропускаются. В панели отдельно показан тип выпуска. Это относится и к автоустановке, если она включена. Автоматическое понижение версии запрещено, даже если GitHub предлагает выпуск старше установленного.

При включённой отсрочке и неизвестной дате публикации автоустановка откладывается до получения даты. Отсрочка не меняет выбор выпуска: в очереди остаётся самая новая подходящая версия.

Порядок установки:

1. Скачать архив **на USB**, проверить размер и официальную SHA-256 из GitHub API или `.dgst`.
2. Распаковать только `xray`, проверить ELF/ARM64, версию и совместимость текущего конфига.
3. Сохранить и проверить прежнее ядро на USB, записать журнал отката в JFFS.
4. Заменить ядро и перезапустить Xray; DNS helper и правила при обычном успешном обновлении сохраняются.
5. Проверить DNS, правила и HTTPS через VPN. При ошибке попытаться восстановить прежнее ядро.

Неудачный выпуск блокируется для автоматических повторов. В интерфейсе можно явно разрешить ручной повтор. За ночь выполняется не больше одной автоматической попытки. Для ручного возврата есть кнопка **«Вернуть предыдущее ядро с USB»**.

Временно оборвутся существующие VPN-соединения. Короткая проверка не гарантирует длительную стабильность XHTTP: после обновления стоит проверить свои приложения. SHA-256 ядра берётся из официального HTTPS-источника; это отдельная проверка, **не Ed25519-подпись панели**.

## Копии, перенос настроек и автоочистка

**Копии и файлы → Копии настроек** содержит последние 12 снимков перед применением изменений. Восстановление меняет список сайтов, DNS и маршруты Telegram.

**Импорт и экспорт** переносит группы и выбор устройств. Пароль и реквизиты серверов в JSON не входят. Импорт сначала открывается для просмотра и сохраняется кнопкой **«Применить изменения»**.

### Автоочистка через неделю

По умолчанию включена; настройка находится в **Копии и файлы → Файлы и очистка**. Первый обход — через две минуты после запуска панели, последующие — каждые шесть часов.

Удаляются известные лишние снимки, прежние ядра и временные файлы проекта **старше семи дней**. Сохраняются:

- текущие программы, пароль, VPN-конфиг, ключи и USB-загрузчик;
- последняя копия панели и последний снимок настроек;
- последняя копия ядра и копия, на которую указывает действующий откат;
- файлы активной операции и данные, необходимые для незавершённого восстановления.

Неизвестные файлы и содержимое соседних папок не удаляются. Символические ссылки не обходятся. При несинхронизированных часах очистка откладывается; даты из периода до синхронизации не используются для автоматического удаления. Свежий файл внутри старой папки также сохраняет папку.

История настроек дополнительно ограничена последними 12 снимками, поэтому при частых изменениях самые старые могут удаляться раньше недели. Журналы в RAM ограничиваются размером независимо от недельной очистки.

## Как работают маршруты

Домены включают поддомены. DNS роутера наполняет IP-наборы групп, после чего выбранный трафик направляется через Xray. Защищённый DNS браузера может обходить этот механизм. Общие CDN-IP могут использоваться несколькими сервисами: активная группа сохраняет нужный ей VPN-маршрут.

Изменение списка обычно не перезапускает Xray. Уже открытое соединение может сохранить прежний маршрут, а ранее найденный IP удалённого домена — остаться в кеше до 24 часов. Для проверки нового правила перезапустите приложение и очистите его DNS-кеш.

Запрет QUIC по умолчанию включён только у YouTube. Пробный режим и временное включение группы возвращают прежний выбор после срока; для этого нужны запущенная панель и синхронизированные часы. Выключенный роутер обработает истёкшие таймеры после следующей загрузки.

## Диагностика и резерв

В **«Диагностике»** доступны отчёт о сбое и проверки зависимостей, в **«Контроле связи»** — история сервисов, в **«Настройке связи»** — сравнение XHTTP и ограниченный тест задержки под нагрузкой. Ответ Cloudflare, HTTP-ошибка или отказ одного сайта не запускают полный перезапуск VPN.

Отчёт исключает сырой конфиг, пароль и известные поля с ключами/адресом VPN-сервера. IPv4 и MAC заменяются метками. В отчёте остаются выбранные проверки и последние ошибки; перед публичной публикацией проверьте свободный текст сторонних сообщений.

Резерв добавляется в **VPN-серверы → Резервный канал**: второй VLESS-профиль или один outbound JSON. Он проверяется отдельным Xray перед сохранением и переключением. Автопереключение выключено до явного включения; автоматического возврата на основной канал нет. Независимость серверов обеспечивает пользователь.

Замеры выполняются с роутера и не заменяют проверку браузера, приложения или Wi-Fi. XHTTP сравнивается в отдельном процессе с запасом не менее 96 МиБ доступной RAM. Короткая нагрузка ограничена 8 МиБ и 8 секундами; настройки QoS ASUS автоматически не меняются.

В **«Диагностике»** выберите ПК или телефон и домен. Проверка учитывает текущий IP, режим устройств, активные и выключенные IP-наборы и исключения маршрутов. Расхождение сохранённого выбора с набором устройств показывается отдельно. Это прогноз TCP-маршрута по правилам; реальный запрос с выбранного устройства и защищённый DNS браузера он не проверяет.

**«Контроль связи → История связи»** показывает уведомления за сутки и сводку HTTPS-проб: наблюдаемое время, интервалы недоступности, число эпизодов ошибок и попыток восстановления, пиковые значения RAM и RSS. Пропуски более 100 секунд считаются неизвестными, а не успешной связью. События можно отметить прочитанными в этом браузере. Уведомления появляются при открытой панели; доставка в Telegram или email не включена.

История проб и ресурсов хранится в RAM с ограничением 512 КиБ на журнал, переживает перезапуск панели и сбрасывается после перезагрузки роутера. Память измеряется раз в минуту; сводка обновляется при открытой вкладке. Периодические замеры не записываются во flash.

## Собственный репозиторий GitHub

Для собственного репозитория нужно настроить подпись выпусков и закрепить его публичный ключ в `assets/github-public-key.txt`. Приватный ключ хранится в GitHub Actions secret, на роутер не передаётся. Порядок сборки и публикации описан в [руководстве разработчика](DEVELOPMENT.md). Обновление уже работающей панели из этого репозитория не требует повторной настройки ключей.
